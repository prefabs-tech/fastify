# 07 — `@prefabs.tech/fastify-s3`

S3 object storage paired with a `files` table, plus the multipart intake for
REST uploads. **This package ships no routes** — it gives you a service, a
client, and a normalised request body, and you write the endpoints.

Peers: `@prefabs.tech/fastify-config`, `@prefabs.tech/fastify-error-handler`,
`@prefabs.tech/fastify-graphql`, `@prefabs.tech/fastify-slonik`, `fastify`,
`fastify-plugin`, `slonik`, `zod`. Bundles the AWS SDK v3 clients,
`@fastify/multipart`, `ajv`, and `uuid`.

## Registration

Register **after** slonik (it throws otherwise) and **after** graphql (so the
multipart parser does not capture GraphQL upload bodies).

```typescript
import s3Plugin from "@prefabs.tech/fastify-s3";

await fastify.register(s3Plugin, {
  bucket: "my-app-uploads",
  clientConfig: {
    credentials: { accessKeyId: "...", secretAccessKey: "..." },
    region: "eu-west-1",
  },
  filenameResolutionStrategy: "add-suffix",
  fileSizeLimitInBytes: 10 * 1024 * 1024,
  rest: { enabled: true },
  table: { name: "files" },
});
```

`S3Options` is `S3Config` plus `rest`:

| Field | Type | Notes |
|---|---|---|
| `clientConfig` | `S3ClientConfig` | Straight to the AWS SDK `S3Client` constructor |
| `bucket` | `string \| Record<string, string>` | Default bucket, or a named map |
| `filenameResolutionStrategy` | `"overwrite" \| "add-suffix" \| "error"` | Global default on key collision |
| `fileSizeLimitInBytes` | `number` | REST upload cap; defaults to `Infinity` |
| `table.name` | `string` | Overrides the `files` table name |
| `rest.enabled` | `boolean` | Registers `@fastify/multipart` when true |

Registration order inside the plugin: throw if `fastify.slonik` is missing →
fall back to `{ ...config.s3, rest: config.rest }` if options are empty →
run the files-table migration → register multipart when `rest.enabled`.

`rest.enabled` may be off entirely. The plugin still migrates and still gives
you `FileService` and `S3Client`, which is the right setup for presigned-URL,
server-generated, and download-only flows.

## Multipart intake

With `rest.enabled`, `@fastify/multipart` is registered with
`attachFieldsToBody: "keyValues"`, `sharedSchemaId: "fileSchema"`, a
`limits.fileSize` from `fileSizeLimitInBytes`, and an `onFile` hook that
normalises every part to:

```typescript
interface Multipart {
  data: Buffer | ReadStream;
  encoding?: string;
  filename: string;
  limit?: boolean;
  mimetype: string;
}
```

So `request.body.photo` is that object, not a stream — buffered in memory. Size
the limit accordingly.

> Verify multipart registration behaviourally
> (`fastify.hasContentTypeParser("multipart/form-data")`); `sharedSchemaId`
> does not expose a schema through `fastify.getSchema`.

### `ajvFilePlugin`

Validating a file field needs a custom AJV keyword. This plugin is passed to
the **Fastify constructor**, not to `register`:

```typescript
import Fastify from "fastify";
import { ajvFilePlugin } from "@prefabs.tech/fastify-s3";

const fastify = Fastify({ ajv: { plugins: [ajvFilePlugin] } });
```

Then `isFile: true` in a route schema validates that the value is a multipart
object (`data` + `filename` + `mimetype`), or an array of them. At compile time
the keyword also rewrites the schema to `type: "string", format: "binary"`, so
OpenAPI renders a file input.

```typescript
schema: {
  body: { properties: { photo: { isFile: true } }, type: "object" },
  consumes: ["multipart/form-data"],
}
```

It is only required if a route schema uses `isFile` — an unknown keyword
otherwise throws at startup. It is an adaptation of `@fastify/multipart`'s
plugin of the same name, not a re-export: this one validates the normalised
`Multipart` shape and adds array support.

## `FileService`

Extends `BaseService<File, FileCreateInput, FileUpdateInput>`, so every method
from chapter 03 is available alongside these.

```typescript
import { FileService } from "@prefabs.tech/fastify-s3";

const service = new FileService(request.config, request.slonik, request.dbSchema);
```

> **`FileService` still reads `config.s3`.** It builds its client from
> `this.config.s3.clientConfig`, reads `this.config.s3.filenameResolutionStrategy`,
> and `FileSqlFactory` reads `this.config.s3?.table?.name`. Passing options to
> `register()` does not change that. Any application using `FileService` — or
> the user package's photo features, which use it internally — must keep an
> `s3` block on the config object handed to services.

### `upload(payload)`

```typescript
const file = await service.upload({
  file: {
    fileContent: request.body.document,          // Multipart
    fileFields: {
      bucket: "my-app-uploads",
      description: "Signed contract",
      uploadedAt: Date.now(),
      uploadedById: request.user.id,
    },
  },
  options: {
    bucketChoice: "optionsBucket",
    filenameResolutionStrategy: "add-suffix",
    path: `contracts/${contractId}`,
  },
});
```

The pipeline: resolve the bucket → compute the key → check existence with
`HeadObject` → apply the collision strategy → upload → insert the row.

**Bucket resolution** (`getPreferredBucket`): an explicit `bucketChoice` picks
`options.bucket` or `fileFields.bucket`; without it, whichever of the two is
set wins, and `fileFields.bucket` takes precedence when both are.

**Key** is `` `${path}/${filename}` `` with the trailing slash normalised. The
filename comes from `fileContent.filename`, gaining the extension if missing;
with no filename set it falls back to `` `${uuidv4()}.${extension}` ``.

**Collision strategies** — only consulted when the key already exists:

| Strategy | Behaviour |
|---|---|
| `"overwrite"` | Proceeds; the object is replaced |
| `"add-suffix"` | Lists objects with the same base name and appends the next free numeric suffix — `report-2.pdf` |
| `"error"` | Throws `CustomError` with `ERROR_CODES.FILE_ALREADY_EXISTS_IN_S3` |

The per-call `options.filenameResolutionStrategy` wins over
`config.s3.filenameResolutionStrategy`. With neither set, the switch matches
nothing and the upload proceeds as an overwrite.

`uploadedAt` and `lastDownloadedAt` are passed through `formatDate` before
insertion. The method returns `undefined` if the S3 upload produced no result.

### Other methods

| Method | Behaviour |
|---|---|
| `download(id, { bucket? })` | Returns the record plus `{ fileStream: Buffer, mimeType }`. Throws `FILE_NOT_FOUND_ERROR` if the row is missing |
| `presignedUrl(id, { bucket?, signedUrlExpiresInSecond? })` | Returns the record plus `{ url }`. Default expiry 3600s |
| `deleteFile(fileId, { bucket? })` | Deletes the row, then the object — in that order. Throws `FILE_NOT_FOUND_ERROR` if the row is missing |

All three resolve the bucket from the option, falling back to the bucket stored
on the file row.

Note `deleteFile` removes the database row **before** the S3 object; a failure
in the S3 call leaves an orphaned object, not an orphaned row.

## `S3Client`

A thin wrapper over `@aws-sdk/client-s3` with a mutable `bucket`, so one
instance serves several buckets.

```typescript
import { S3Client } from "@prefabs.tech/fastify-s3";

const client = new S3Client(config.s3.clientConfig);
client.bucket = "my-app-uploads";
```

| Method | Returns |
|---|---|
| `upload(fileStream, key, mimetype)` | Multipart-capable upload via `@aws-sdk/lib-storage` |
| `get(filePath)` | `{ Body: Buffer, ContentType }` — the stream is consumed internally |
| `delete(filePath)` | `DeleteObjectCommandOutput` |
| `generatePresignedUrl(filePath, originalFileName, expiresIn = 3600)` | URL forcing `Content-Disposition: attachment` |
| `getObjects(baseName)` | `ListObjectsCommandOutput` for the prefix |
| `isFileExists(key)` | `true`, `false` on `NotFound`, rethrows anything else |

## Database

One table, `files` (or `table.name`), created idempotently at registration.
Columns: `id`, `original_file_name`, `bucket`, `description`, `key`,
`uploaded_by_id`, `uploaded_at`, `download_count` (default `0`),
`last_downloaded_at`, `created_at`, `updated_at`. See
[chapter 13](13-database-schema.md).

`@prefabs.tech/fastify-user` declares foreign keys into this table, which is
why s3 must register first.

## Error codes

| Constant | Value | Thrown by |
|---|---|---|
| `ERROR_CODES.FILE_NOT_FOUND` | `"FILE_NOT_FOUND_ERROR"` | `download`, `presignedUrl`, `deleteFile` |
| `ERROR_CODES.FILE_ALREADY_EXISTS_IN_S3` | `"FILE_ALREADY_EXISTS_IN_S3_ERROR"` | `upload` with strategy `"error"` |

Both are `CustomError`s, so they surface as opaque 500s unless mapped — see
chapter 02.
