# fastify-s3

**Responsibility:** persist file metadata in Postgres and the file bytes in an S3-compatible bucket, and parse REST multipart bodies. The GraphQL upload transport no longer lives here; it is in [graphql](graphql.md).

## Registration
1. Throw if `fastify.slonik` is missing.
2. Resolve options, or fall back to `{ ...config.s3, rest: config.rest }`.
3. Run `CREATE TABLE IF NOT EXISTS files`. The name comes from `table.name` or the constant `TABLE_FILES`.
4. If `rest.enabled` is truthy, register `@fastify/multipart`:
   - `attachFieldsToBody: "keyValues"`
   - `limits.fileSize = fileSizeLimitInBytes || Infinity`
   - `sharedSchemaId: "fileSchema"`
   - an `onFile` hook that replaces each part with `{ data: Buffer, encoding, filename, mimetype }`, buffering the whole file in memory.[^plugin]

## `files` table
`id`, `original_file_name`, `bucket`, `description`, `key`, `uploaded_by_id` (nullable), `uploaded_at`, `download_count`, `last_downloaded_at`, `created_at`, `updated_at`.[^queries]

`uploaded_by_id` was made nullable by editing the `CREATE TABLE` statement.[^commit-uploaded-by] Existing tables keep their original constraint; see [Package schema migrations](../operations/package-schema-migrations.md).

## `FileService`
It extends `BaseService<File, FileCreateInput, FileUpdateInput>` and **reads `this.config.s3`** for the client config, the default resolution strategy, and the table name.[^service] See [Plugin options migration](../architecture/plugin-options-migration.md#where-the-old-shape-is-still-load-bearing).

### `upload({ file: { fileContent, fileFields }, options })`
1. `fileExtension` comes from the original filename. `filename` defaults to `<uuid>.<ext>` unless the service's `filename` was set beforehand; user sets it to `photo`.
2. `key = <path>/<filename>`.
3. Bucket: `getPreferredBucket(options.bucket, fileFields.bucket, bucketChoice)`.[^utils]
   - An explicit `bucketChoice` wins if that source is set.
   - Otherwise whichever source is set is used.
   - If both are set and differ, the `fileFields` bucket wins.
4. `HeadObject` checks for an existing key. If it exists, the strategy is `options.filenameResolutionStrategy || config.s3.filenameResolutionStrategy`:
   - `error`: throws `CustomError(FILE_ALREADY_EXISTS_IN_S3)`.
   - `add-suffix`: lists by base-name prefix and picks `<base>-<max+1>.<ext>`.
   - `overwrite`, **or no strategy at all**: falls through and overwrites.[^service][^constants]
5. The upload uses `@aws-sdk/lib-storage` `Upload`.[^client]
6. **Then** the files row is inserted, with `formatDate` applied to `uploadedAt`/`lastDownloadedAt`, plus `key` and `originalFileName`.
   > Inference: the S3 write and the row insert are not transactional. A failed insert leaves an orphaned object.

### Other methods
- `download(id)`: loads the row, then fetches **the whole object into a Buffer**.[^client]
- `presignedUrl(id, { signedUrlExpiresInSecond })`: default 3600 s, with `Content-Disposition: attachment; filename="<original>"`.[^client]
- `deleteFile(id)`: deletes the row first, then the object if a row was deleted. Throws `FILE_NOT_FOUND` when the row is absent.[^service]

## Other exports
- `ajvFilePlugin(ajv)`: adds an `isFile` keyword. At compile time it rewrites the schema to `type: string, format: binary` (so docs show a file picker); at runtime it validates `{ data, filename, mimetype }` or an array of them.[^ajv] The app has to add it to Fastify's Ajv plugins itself.
- `S3Client` wrapper, `FileService`, table and error constants, and the types.[^index]
- **Deprecated:** `multipartParserPlugin` now just registers graphql's transport unless it is already present, and warns.[^deprecated-parser] The `GraphQLUpload` type re-exports and the `ApiConfig.s3` augmentation are also deprecated.

## Config (`S3Config`)
`bucket` (a string or a map), `clientConfig: S3ClientConfig` (passed straight to the AWS SDK), `filenameResolutionStrategy?`, `fileSizeLimitInBytes?`, `table.name?`.[^types] Using the AWS SDK's own client config was a breaking change.[^commit-client-config]
